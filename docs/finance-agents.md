# Finance Agents

AI agents that analyze personal and business finances — assets, liabilities,
income, and expenses — and propose a path forward: paying down debt
efficiently and building business credit across the family's companies.
**Every agent-generated action requires human approval before anyone acts on
it.** No agent moves money, opens a credit line, or submits an application.

This module lives alongside InRange's real-estate lead-gen pipeline in the
same repo/Supabase project, but in its own `finance` Postgres schema and its
own set of edge functions (`finance-*`) — it does not touch the `public`
schema tables that back the lead-gen product.

## Why human approval is structural, not a UI checkbox

Every recommendation an agent produces is written to
`finance.agent_recommendations` with `status = 'pending'`. Nothing else in
this codebase reads `status = 'approved'` and takes a real-world action —
there is no auto-pay, no auto-apply. The only way a row leaves `pending` is
through `finance-approvals`, and even an `'approved'` row still requires a
human to go execute it (make the payment, open the account, etc.) outside
this system. See `docs/finance-approval-workflow.md` for the full lifecycle.

## Architecture

```
Manual entry / CSV import           (Plaid sync: schema stub only, not implemented)
  │
  ▼
Supabase Postgres — `finance` schema
  entities, accounts, income_sources, expenses, transactions
  │
  ▼
Supabase Edge Functions (Deno/TypeScript) — the agents
  finance-analyze          → net worth, cash flow, DTI, utilization snapshot
  finance-debt-payoff       → avalanche/snowball payoff simulation + plan
  finance-credit-builder    → business-credit-building playbook + next steps
  │  every agent run may also INSERT into agent_recommendations (status='pending')
  ▼
finance.agent_recommendations  ←──  finance-approvals (the only write path out of 'pending')
  │
  ▼
Human reviews finance.pending_recommendations (via Supabase Studio, a
future dashboard, or direct SQL) and approves/rejects via finance-approvals
```

## The three agents

### `finance-analyze`
Reads an entity's (or every entity's) accounts, income, and expenses;
computes total assets, total liabilities, net worth, monthly cash flow,
debt-to-income, and aggregate revolving credit utilization. Writes a
`financial_snapshots` row. Files a `spending_alert` recommendation on
negative cash flow, and a `credit_building` recommendation when utilization
exceeds 30%.

### `finance-debt-payoff`
Given a monthly budget for debt payments (a human-supplied number — the
agent doesn't guess how much you can afford), simulates both **avalanche**
(highest APR first) and **snowball** (smallest balance first) payoff
schedules across an entity's liability accounts. Writes a `debt_payoff_plans`
row + ordered `debt_payoff_steps` for each strategy computed, and files one
`debt_payoff` recommendation naming the lower-interest strategy — with the
tradeoff spelled out if the alternative pays off faster despite costing more.

### `finance-credit-builder`
For a single business entity, compares its `business_credit_profiles` row
against a standard business-credit-building playbook (EIN → dedicated bank
account → D-U-N-S number → net-30 vendor tradelines → starter business card
→ credit monitoring → 6-12 months of on-time payment history → revolving
credit line) and recommends the next 1-2 unmet steps. See
`docs/finance-business-entities.md` for the full playbook and how it applies
to each of the six businesses.

All three agents write a human-readable `rationale` on every recommendation.
If `ANTHROPIC_API_KEY` is set, that text is generated by Claude; if not, a
deterministic template is used instead — the agents work either way.

## What's deliberately NOT built yet

- **Live bank/credit sync (Plaid).** `finance.plaid_items` and
  `accounts.data_source = 'plaid'` exist as a schema-level integration point,
  but no Plaid API calls are made. Balances and transactions come in via
  `finance-import-transactions` (manual/CSV) or direct inserts today.
- **Any automated execution.** No agent submits a credit application, opens
  a vendor account, or initiates a payment. Approval marks something as
  authorized; a human still does the real-world step.
- **A dashboard UI.** `finance.pending_recommendations`,
  `finance.entity_balance_sheet`, and `finance.credit_building_status` are
  views meant to back one (Retool, a custom app, or direct SQL/Studio) —
  none is wired up in this pass.

## Setup

Same Supabase project as InRange's lead-gen pipeline:

```bash
supabase db push          # applies the finance schema migrations too
supabase functions deploy finance-analyze finance-debt-payoff \
  finance-credit-builder finance-import-transactions finance-approvals
```

Edge Function secrets (Supabase Dashboard → Edge Functions → Secrets):

```
ANTHROPIC_API_KEY        = sk-ant-...          # optional — enables AI-written rationale text
ANTHROPIC_MODEL          = claude-sonnet-4-6    # optional override
FINANCE_WEBHOOK_SECRET   = (shared secret; openssl rand -hex 32)
```

## Local testing

```bash
supabase start
supabase functions serve

# Seed a liability account first (Studio, SQL, or your own insert), then:
curl -X POST http://localhost:54321/functions/v1/finance-analyze \
  -H "Content-Type: application/json" -d '{}'

curl -X POST http://localhost:54321/functions/v1/finance-debt-payoff \
  -H "Content-Type: application/json" \
  -d '{"entity_id": "<household-uuid>", "monthly_budget": 1200}'

curl -X POST http://localhost:54321/functions/v1/finance-approvals \
  -H "Content-Type: application/json" \
  -d '{"recommendation_id": "<uuid>", "decision": "approve", "decided_by": "you"}'
```
